# Defect register

| ID | Severity | Reproduction and observed result | Cause and change | Retest |
| --- | --- | --- | --- | --- |
| QA-01 | P1 | Start the baseline runtime host in a disposable profile and kill the parent. Five of five owned service processes survived. | Electron directly owned the runtime. A separate bundled Node supervisor now holds service handles and performs cleanup when its IPC channel closes. | Installed forced-exit test records service process identities, checks the gateway closes and relaunches the same profile. |
| QA-02 | P1 | A crawl row left in a running stage had no startup reconciliation. A cancelled crawl also could finish before the worker's cancellation poll and overwrite the cancellation. | Desktop startup reconciles interrupted records before the worker is ready and deduplicates pending queue submissions. Atomic status predicates prevent cancellation from being overwritten by finalization. | The worker fixture cancels before its next poll. The packaged fault fixture injects interrupted and completed database states to verify reconciliation and preservation. |
| QA-03 | P1 | The first supervisor candidate finished its live workflow and stopped its services, but Electron remained open at quit. | Explicit stop message, supervisor process-exit acknowledgement, and final Electron exit after cleanup. | Installed close and relaunch in the final build. |
| QA-04 | P2 | A fixture occupied the allocated interface port before Next could bind. Startup exited with `EADDRINUSE`. | Verify that the owned child bound its listener before probing. Retry confirmed bind conflicts with new ports. | Passed the same controlled contention test. |
| QA-05 | P1 verification gap | 0.1.2 tested seeded interruption state only. | Added deterministic live barriers and actual packaged immediate relaunch. | All mandatory scenarios passed. See [live recovery results](LIVE_RECOVERY_REPORT.md). |
| LR-D01 | P1 | The retained 0.1.2 worker exposed score 89 to another database connection while the audit status was running. | Findings, score and audit completion now share a transaction. Restart also removes any partial findings from interrupted legacy runs. | LR-08 and LR-10 confirmed an independent reader sees no partial results before commit. |
| LR-D02 | P1 | Replaying the performance job changed a failed sample to completed and replaced a previously completed measurement. | Stable desktop queue identifiers and terminal sample preservation make replay safe. | LR-09 verified a deliberate replay consumes the job while preserving exact recorded sample values. |
| LR-D03 | P1 | Killing Electron releases its process lock while the old database can still be active. | Startup waits for the previous PostgreSQL process to release storage. | LR-12 launched the replacement while the old PostgreSQL process was alive. |
